\chapter{Introduction}
\label{ca:chap:intro}

Much of the knowledge a practitioner would like to train on is no longer available as
data. Hospitals, banks and firms rarely release their datasets, but they increasingly
expose models trained on them, through an interface or as open weights. For anyone training a small language model, the resource at
hand is therefore less often a dataset and more often a set of models to query, each with
its own price and competence. On-policy distillation, in which the student learns from its
own responses as scored by a teacher \autocite{agarwal_gkd_2024,gu_minillm_2024}, is a
natural way to learn from such models.

This project started from FedTOPS \autocite{chen_fedtops_2026}, the first study of
on-policy distillation in a federated setting. It found that a student's progress changes
what it can next learn from its teacher. FedTOPS has one teacher, reads its token
probabilities, and treats every query as free. We drop all three assumptions. If a
student's progress changes what it can learn from a teacher, it should also change which
of several priced, text-only teachers is worth paying for.

The usual default is to query the strongest model. However, small models (3B parameters or
fewer) often learn more from smaller teachers than from strong reasoners
\autocite{li_learnability_gap_2025}, and a larger teacher does not necessarily give a
better student \autocite{guo_lada_2026}. We therefore study the following problem, which
we term provider-selective distillation.

\begin{mdframed}[backgroundcolor=bg, linewidth=0pt, innertopmargin=8pt,
  innerbottommargin=8pt]
Given a fixed query budget and several black-box providers whose usefulness is unknown,
domain-dependent and changing, how should a student decide whom to ask, about what, and
when?
\end{mdframed}

It differs from online data mixing \autocite{albalak_odm_2023} and LLM routing
\autocite{ong_routellm_2025} in one essential way: every query changes the student, and
with it the value of every provider at the next decision. To study it, we (1) build a
reproducible testbed with priced black-box providers, including a corrupted one; (2)
measure the value of each provider directly, by training from shared student checkpoints
on one provider at a time; and (3) design budget-aware selectors and compare them with
fixed allocations. Figure~\ref{ca:fig:teaser} summarises the main result so far. Cheap
providers teach about as fast per gradient step as expensive ones, so price decides value
(Takeaway~\ref{ca:tk:price}). Our selector reaches the highest test utility of any
condition, 0.500 against 0.494 for the best single provider, but the difference is within
noise (Takeaway~\ref{ca:tk:h3}).

\section{Objectives and Scope}
\label{ca:sec:objectives}

The project has four objectives: to build the testbed; to test whether the best provider
differs by domain (H1) and changes during training (H2); to design selectors and test
whether adaptivity beats the best fixed allocation (H3); and to explain where learning
happens and what the selectors spend on. Strategic providers, providers that learn from
the student, formal privacy guarantees and logit-level distillation are out of scope.
Tasks are single-turn with checkable answers, so that rewards are cheap and need no learned
judge.
